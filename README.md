# mytracker

Личный каталог фильмов, аниме и сериалов на Kotlin Multiplatform и Compose Multiplatform. Целевая платформа приложения — настольная Windows/JVM.

## Возможности

- Главный экран со сводкой по коллекции.
- Каталог всех произведений и разделы «Фильмы», «Аниме» и «Сериалы».
- Группировка записей по статусам: «Хочу посмотреть», «Просмотрено», «Брошено».
- Добавление произведения через динамический поиск TMDB или вручную, с категорией, статусом и личной заметкой. Фильмы и сериалы аниме хранятся отдельно от обычных фильмов и сериалов.
- Для статуса «Просмотрено» требуется оценка от 1 до 5; при создании просмотренной записи можно сразу добавить рецензию.
- Редактирование статуса, оценки, рецензии и личных заметок. В карточке «Готово» сохраняет изменения, а «Назад» отменяет их.
- Заметки о просмотре с системной датой. В интерфейсе дата отображается в формате `ДД.ММ.ГГГГ`.
- Сезоны сериалов и аниме-сериалов загружаются из TMDB: отображаются название сезона, количество эпизодов и дата премьеры, если они доступны. Для всего сериала и каждого сезона независимо можно задать необязательные оценку и рецензию; ручное добавление сезонов не поддерживается.
- Удаление произведений с подтверждением и удаление личных заметок.
- Локальное сохранение каталога между запусками.

Поиск использует TMDB API и всегда проверяет фильмы и сериалы, независимо от выбранной в форме категории; выбранный тип служит только для приоритета результатов. Тип TMDB-результата автоматически задаёт тип категории (фильм или сериал), а загруженные метаданные автоматически уточняют её до аниме-фильма или аниме-сериала при наличии совпадения. Результаты прямого поиска обновляются через 300 мс после паузы во вводе. Если прямой поиск ничего не нашёл, через 1500 мс запускается поиск с вариантами написания: `е/ё`, другая раскладка клавиатуры, русская транслитерация и буквы с диакритикой. Результаты показываются под полем названия вместе с постерами; список результатов прокручивается независимо от остальной карточки.

При ответе TMDB `429 Too Many Requests` пауза прямого поиска увеличивается; после успешных запросов она постепенно возвращается к исходным 300 мс. Для обычных фильмов/сериалов и аниме-фильмов/сериалов используются соответствующие каталоги TMDB, а для общей категории «Аниме» проверяются оба. После выбора результата приложение анализирует ключевые слова и подробности TMDB: явное ключевое слово об аниме или сочетание жанра «анимация» с японским языком/происхождением автоматически уточняют категорию; её можно изменить вручную. Одна только анимация или японское происхождение не считаются достаточными. После выбора результата в карточке добавления показываются название, год выпуска, страна производства и постер. URL постера, год и страны сохраняются в записи; год и страны отображаются рядом с названием в каталоге. Постер также отображается в карточке произведения и открывается крупнее по нажатию; изображения загружаются и кэшируются локально. Страна загружается из подробностей TMDB; для сериалов используется страна происхождения, если список стран производства отсутствует. Выбранный результат сохраняет внешний идентификатор и тип записи (`movie` или `tv`). Личные статусы, общие и сезонные оценки и рецензии остаются данными приложения. Метаданные сезонов и число эпизодов загружаются из TMDB.

Для доступа к API нужен токен **API Read Access Token** из настроек API аккаунта TMDB. Для запуска из PowerShell задайте его в переменной среды:

```powershell
$env:TMDB_API_READ_ACCESS_TOKEN = 'ваш токен'
.\gradlew.bat run
```

В IntelliJ IDEA укажите `TMDB_API_READ_ACCESS_TOKEN` в переменных среды конфигурации запуска. Не добавляйте токен в файлы проекта или Git.

Для некоммерческого использования приложение показывает официальную атрибуцию TMDB в разделе «О приложении». Актуальные требования приведены в [документации TMDB](https://developer.themoviedb.org/docs/faq).

## Хранение данных

Каталог хранится в файле `~/.mytracker/catalog.dat` в домашней папке пользователя. В Windows это обычно `%USERPROFILE%\.mytracker\catalog.dat`.

Для каталога поддерживается единый бинарный формат версии 8; файлы версии 7 автоматически однократно преобразуются в него с сохранением записей и метаданных сезонов. Другие несовместимые версии не перезаписываются: приложение показывает ошибку и путь к файлу. Запись выполняется через временный файл с последующей заменой основного; при ошибке приложение сохраняет исходный файл и состояние каталога.

## Требования

- JDK 25 для настроенного Gradle toolchain.
- Gradle Wrapper загружает Gradle 9.8.2 автоматически.

JVM-байткод проекта нацелен на Java 21. Wrapper запускается с Java, указанной через `JAVA_HOME` или `PATH`.

## Запуск из PowerShell

Укажите `JAVA_HOME` на установленный JDK, затем из корня проекта выполните:

```powershell
$env:JAVA_HOME = 'C:\путь\к\JDK'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
.\gradlew.bat run
```

В IntelliJ IDEA выберите Gradle JVM в **Settings → Build, Execution, Deployment → Build Tools → Gradle** и запустите Gradle-задачу `run`.

## Тесты

Запустить JVM-тесты из PowerShell:

```powershell
.\gradlew.bat jvmTest
```

На GitHub Actions задача `jvmTest` автоматически запускается на Windows для pull request в репозиторий и push в `main`; её также можно запустить вручную. Gradle и зависимости кэшируются. `jvmTest` компилирует приложение и тесты, затем запускает тесты, включая Compose UI-сценарии.

JVM-тесты покрывают файловое хранилище и миграцию формата, валидацию записей, классификацию аниме, поиск и обработку сетевых ошибок TMDB, генерацию ID и Compose UI-сценарии.

## Структура проекта

- `src/commonMain` — Compose-интерфейс и общие модели данных.
- `src/jvmMain` — JVM-точка входа и локальное файловое хранилище.
- `src/jvmTest` — JVM-тесты моделей, TMDB-клиента, хранилища и Compose UI.
- `gradle/wrapper` — версия Gradle Wrapper.
