# План развития mytracker

План отражает текущее направление проекта. Архитектуру, API и формат хранения будем уточнять по мере появления требований, а не фиксировать заранее.

## Уже реализовано в прототипе

- Настольное приложение для Windows на Kotlin/JVM и Compose Multiplatform.
- Главный экран, каталог и категории «Фильмы», «Аниме», «Сериалы».
- Группировка каталога по статусам: «Хочу посмотреть», «Просмотрено», «Брошено».
- Добавление и удаление произведений; подтверждение удаления.
- Изменение статуса, оценки и рецензии с сохранением по кнопке «Готово» и отменой по кнопке «Назад».
- Личные заметки с системной датой; заметки можно добавлять и удалять.
- Просмотр сезонов и заметки к ним. Ручное добавление сезонов отключено.
- Динамический поиск фильмов, сериалов и аниме через TMDB: прямой запрос после 300 мс паузы, затем — поиск вариантов написания после 1500 мс, если прямой поиск пуст. Поддерживаются варианты `е/ё`, неверная раскладка, русская транслитерация латиницей и диакритика. Для `429` действует адаптивное увеличение задержки.
- Результаты TMDB выводятся прямо под полем названия; список результатов прокручивается отдельно от всей карточки добавления. Выбранный результат сохраняет внешний ID и тип записи; в свёрнутом блоке выбора показываются название, год и страна производства.
- Для новых произведений используются UUID; перед добавлением ID проверяется на совпадение с уже существующими в каталоге.
- Локальное файловое хранилище с версионированием и тестами чтения, записи и миграций.
- Ошибки чтения и записи каталога показываются пользователю с причиной и путём к файлу. Если каталог не удалось прочитать, запись заблокирована; неуспешное сохранение не меняет состояние в интерфейсе и оставляет исходный файл.

## Развитие интеграции TMDB

- Источник выбран: TMDB для фильмов, сериалов и аниме. Поиск для аниме проверяет каталоги фильмов и сериалов, поскольку TMDB не выделяет аниме в отдельный тип.
- По результатам поиска сохранять внешний ID и тип записи TMDB (`movie` или `tv`); личные статусы, оценки и заметки остаются данными приложения.
- Подгружать сезоны и эпизоды для записей типа `tv`; ручное создание сезонов не планируется.
- Поэтапно обновлять интерфейс данными TMDB: показывать в списке каталога и карточке произведения постер, год, описание, жанры и другие полезные метаданные; определить состояния загрузки, отсутствующих данных, ошибок и офлайн-режима. Кэшировать метаданные, не смешивать внешние рейтинги с личной оценкой и сохранять локальный каталог доступным без сети.
- Обработать отсутствие сети, ошибки API, лимиты запросов и недоступность источника; локальный каталог должен оставаться доступным офлайн.
- Перед распространением приложения проверить требования TMDB к ключам API и атрибуции.

## Хранение данных и надёжность

- Выбрать формат хранения перед крупной интеграцией: версионированный файл, локальная БД (например, SQLite) или серверная БД (например, PostgreSQL).
- Сравнить варианты по работе офлайн, резервному копированию, синхронизации между устройствами, развёртыванию и сопровождению. PostgreSQL оправдан при наличии серверного сценария; для локального приложения отдельно оценить SQLite.
- После выбора хранилища определить границу репозитория, транзакции и необходимость выполнять операции вне UI-потока.
- Перед релизом решить, нужны ли миграции старых данных. Если каталог всё ещё содержит только тестовые данные и совместимость не нужна, можно удалить тестовое хранилище и оставить чистую схему одной версии. Если появятся реальные пользовательские данные, миграции и резервное копирование нужно сохранить.
